## :dart: O guia para alavancar a sua carreira

> WordPress move 40,7% de todos os sites da internet e 58,9% dos sites que usam algum CMS conhecido ([w3techs](https://w3techs.com/technologies/details/cm-wordpress)) — nenhuma outra tecnologia web chega perto desse tamanho. Isso significa uma quantidade enorme de trabalho real: criar e manter sites para clientes, desenvolver temas e plugins, cuidar de performance e segurança, migrar para o Editor de Blocos (Gutenberg) e, cada vez mais, integrar IA ao fluxo de edição. Este guia reúne roadmap, documentação oficial, cursos, livros, canais, ferramentas, projetos práticos e comunidades sobre WordPress, com prioridade para conteúdo gratuito e em português. Serve tanto para quem vai publicar o primeiro blog quanto para quem quer virar desenvolvedor(a) de temas e plugins. Todo link foi verificado na data da última revisão — guarde nos favoritos e volte sempre que precisar de uma trilha confiável.

## 🗺️ Roadmap
- [Make WordPress Core](https://make.wordpress.org/core/) — canal oficial de desenvolvimento do núcleo: é onde cada ciclo de versão é planejado e anunciado primeiro.
- [Field Guides de cada versão](https://make.wordpress.org/core/tag/field-guide/) — resumo técnico oficial do que muda em cada versão nova do WordPress, publicado a cada lançamento.
- [WordPress 7.1 "Mary Lou"](https://wordpress.org/news/2026/08/mary-lou/) — anúncio oficial da versão mais recente (agosto de 2026): um bom jeito de ver o roadmap em ação.
- [Todas as versões do WordPress](https://wordpress.org/download/releases/) — histórico completo de lançamentos, do 1.0 até a versão atual.
- [Sobre o WordPress](https://wordpress.org/about/) — a filosofia do projeto (as "quatro liberdades" do software livre) e como as decisões são tomadas.

**Trilha resumida** (siga na ordem; cada etapa tem recursos nas seções abaixo):

1. **Instalação e primeiros passos** — instalar o WordPress, entender o painel de administração (wp-admin), criar a primeira página e o primeiro post.
2. **Editor de Blocos (Gutenberg)** — blocos, padrões (patterns), templates e a diferença entre tema clássico e tema de blocos.
3. **Temas** — instalar e customizar um tema pronto, entender a Edição Completa do Site (Full Site Editing) e o `theme.json`.
4. **Plugins essenciais** — SEO, cache, segurança, formulários e backup: os cinco tipos de plugin que praticamente todo site usa.
5. **WooCommerce** — transformar o site em loja virtual, se o objetivo for e-commerce.
6. **Desenvolvimento de temas** — HTML, CSS e PHP aplicados a temas WordPress, hierarquia de templates, `functions.php`.
7. **Desenvolvimento de plugins** — hooks (actions e filters), Custom Post Types, metadados e a REST API.
8. **Avançado** — WP-CLI, ambientes locais de desenvolvimento, Bedrock/Composer, testes, segurança e otimização de performance.

## 🚀 Por onde começar
1. **Baixe e instale o WordPress** pelo [site oficial](https://wordpress.org/download/) seguindo o [guia oficial de instalação](https://wordpress.org/support/article/how-to-install-wordpress/), ou comece sem hospedagem própria em [WordPress.com](https://wordpress.com/).
2. **Confira os requisitos** no [guia oficial de requisitos](https://wordpress.org/about/requirements/) antes de escolher a hospedagem.
3. **Leia os primeiros passos** — [First Steps with WordPress](https://wordpress.org/support/article/first-steps-with-wordpress/) explica o painel de administração, posts, páginas e comentários.
4. **Faça o curso oficial e gratuito para iniciantes** — [Beginner WordPress User](https://learn.wordpress.org/course/beginner-wordpress-user/) no Learn WordPress, mantido pela própria comunidade.
5. **Siga uma trilha de aprendizagem** — o [caminho para quem usa o WordPress no dia a dia](https://learn.wordpress.org/learning-pathway/user/) organiza os cursos oficiais em ordem.
6. **Construa um site completo guiado** — o curso [Creating a 4-Page Business Website](https://learn.wordpress.org/course/creating-a-4-page-business-website/) leva do zero a um site de quatro páginas.
7. **Entre na comunidade brasileira** — o site oficial [br.wordpress.org](https://br.wordpress.org/) tem notícias, tutoriais e eventos em português.
8. **Aprofunde-se em desenvolvimento** — quando o básico estiver confortável, siga para o [caminho de quem desenvolve para WordPress](https://learn.wordpress.org/learning-pathway/developer/) e para a seção de Documentação oficial abaixo.

## 📖 Documentação oficial
- [Central de documentação (WordPress.org)](https://wordpress.org/documentation/) — ponto de entrada oficial para toda a documentação de uso do WordPress.
- [Developer Resources](https://developer.wordpress.org/) — hub oficial com todos os manuais (handbooks) para quem desenvolve temas, plugins e integrações.
- [Theme Developer Handbook](https://developer.wordpress.org/themes/) — manual oficial de desenvolvimento de temas, do clássico ao tema de blocos.
- [Plugin Developer Handbook](https://developer.wordpress.org/plugins/) — manual oficial de desenvolvimento de plugins: hooks, segurança, banco de dados.
- [Block Editor Handbook](https://developer.wordpress.org/block-editor/) — documentação oficial do Gutenberg: criação de blocos, Interactivity API, Site Editor.
- [REST API Handbook](https://developer.wordpress.org/rest-api/) — referência oficial da API REST do WordPress, usada por apps, temas headless e integrações.
- [Coding Standards](https://developer.wordpress.org/coding-standards/) — padrões oficiais de código PHP, HTML, CSS e JavaScript do projeto.
- [WP-CLI — Commands](https://developer.wordpress.org/cli/commands/) — referência de todos os comandos da ferramenta de linha de comando oficial.
- [Advanced Administration Handbook](https://developer.wordpress.org/advanced-administration/) — administração avançada: segurança, desempenho, multisite, linha de comando.
- [APIs Handbook](https://developer.wordpress.org/apis/) — visão geral das principais APIs internas do WordPress (Options, Transients, HTTP, Settings).
- [Segurança em plugins (handbook)](https://developer.wordpress.org/plugins/security/) — checklist oficial de segurança para quem publica plugins.
- [Glossário oficial do WordPress](https://wordpress.org/documentation/article/wordpress-glossary/) — definições dos termos usados na documentação (loop, hook, taxonomia, etc.).
- [Fórum de suporte oficial](https://wordpress.org/support/forums/) — onde tirar dúvidas diretamente com voluntários e a comunidade.
- [br.wordpress.org](https://br.wordpress.org/) — site oficial em português: notícias, downloads, plugins e temas traduzidos.
- [WP-CLI (site oficial)](https://wp-cli.org/) — site do WP-CLI, a interface de linha de comando oficial para gerenciar instalações WordPress.
- [Novidades para desenvolvedores](https://developer.wordpress.org/news/) — blog oficial com anúncios técnicos de cada versão.
- [Full Site Editing](https://fullsiteediting.com/) — site da comunidade dedicado a explicar a Edição Completa do Site e temas de blocos.
- [Código-fonte do núcleo (GitHub)](https://github.com/WordPress/wordpress-develop) — repositório oficial de desenvolvimento do WordPress.
- [Código-fonte do Gutenberg (GitHub)](https://github.com/WordPress/gutenberg) — repositório oficial do Editor de Blocos.

## 🤖 IA na prática
WordPress está no meio de uma mudança real: de "gerenciador de conteúdo" para "plataforma que agentes de IA também operam". Isso já aparece em três frentes concretas — geração de conteúdo dentro do editor, construção de sites inteira por IA, e servidores MCP que dão a assistentes como Claude acesso direto a um site WordPress (ler posts, criar rascunhos, gerenciar plugins) sem sair do terminal ou do chat.

**Para aprender**
- Faça o curso oficial e gratuito [AI Literacy Through WordPress](https://learn.wordpress.org/course/ai-literacy-through-wordpress/) — feito pela própria equipe do Learn WordPress, cobre o que a IA acerta e erra no contexto do CMS.
- Peça para uma IA **explicar um hook** (`add_action`, `add_filter`) que você encontrou em um plugin de terceiros antes de alterá-lo — cole o trecho de código junto com a pergunta.
- Peça exemplos de **Custom Post Types e campos personalizados** (ACF) para o seu caso de uso específico, e depois confira cada parâmetro na [Function Reference oficial](https://developer.wordpress.org/plugins/).
- Use a IA para **traduzir e revisar strings** de internacionalização (`__()`, `_e()`) ao preparar um tema ou plugin para outros idiomas.

**Para trabalhar**
- [GitHub Copilot](https://github.com/features/copilot) e [Cursor](https://cursor.com/) ajudam bastante em PHP, JavaScript (React) do Gutenberg e CSS de temas — aceleram a escrita de blocos personalizados e templates.
- [Claude Code](https://code.claude.com/docs/en/overview) funciona bem para depurar erros de PHP direto no terminal, revisar plugins antes de instalar e escrever testes para funções de tema.
- O [Model Context Protocol Server da Automattic](https://github.com/Automattic/wordpress-mcp) conecta um site WordPress real a assistentes de IA compatíveis com MCP: o agente pode listar posts, criar rascunhos e consultar configurações do site diretamente.
- Dentro do próprio WordPress, o [Jetpack AI](https://jetpack.com/ai/) traz assistente de escrita, geração de imagens e resumo de conteúdo direto no editor de blocos.
- Ferramentas como o [10Web AI Website Builder](https://10web.io/ai-website-builder/) geram um site WordPress inteiro (layout, textos e imagens) a partir de uma descrição em texto — útil para prototipar rápido, mas sempre revise o resultado.
- Plugins como o [AI Engine](https://wordpress.org/plugins/ai-engine/) e o [AI Power (GPT3 AI Content Generator)](https://wordpress.org/plugins/gpt3-ai-content-generator/) integram modelos de IA ao editor para gerar rascunhos, resumos e imagens sem sair do painel.

**Limites e boas práticas**
- IA **inventa nomes de funções e hooks** que não existem no WordPress core nem nos plugins mais usados — sempre confira na [Function Reference oficial](https://developer.wordpress.org/plugins/) antes de usar em produção.
- Nunca cole **senhas, chaves de API ou dados de clientes** (inclusive do `wp-config.php`) em ferramentas de IA sem verificar a política de privacidade do serviço.
- Código de plugin sugerido por IA que usa `eval()`, concatena SQL diretamente ou ignora `nonce`/sanitização é um risco real de segurança — trate como rascunho, não como produto final.
- Conteúdo gerado por IA para o blog ou para descrições de produto ainda deve passar por revisão humana antes de publicar — tanto por qualidade quanto por SEO.
- Ao instalar um plugin de IA de terceiros, confira as mesmas coisas que conferiria em qualquer plugin: quando foi atualizado pela última vez, quantas instalações ativas tem e as avaliações no [repositório oficial de plugins](https://wordpress.org/plugins/).
